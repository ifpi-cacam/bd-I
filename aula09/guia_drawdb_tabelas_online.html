Banco alvo

Escolha o tipo de banco

01

Ao criar o diagrama, o drawDB pode pedir o dialeto do banco de dados.

Generic

Recomendado para a aula

Use quando o objetivo for apenas representar tabelas, campos e relacionamentos sem depender de um SGBD específico.

MySQL/PostgreSQL/etc.

Quando houver SGBD definido

Use se o professor pedir um banco específico ou se a atividade exigir tipos próprios.

Tipos

Não complique no início

Para a primeira versão, priorize nomes de campos, PKs e FKs. Depois ajuste os tipos.

Na dúvida: escolha Generic para focar na modelagem relacional.
Tabelas

Crie uma tabela por relação

02

Cada relação escrita no modelo relacional deve aparecer como uma tabela no drawDB.

ALUNO = (matricula PK, nome, email, id_curso FK -> CURSO(id_curso)) CURSO = (id_curso PK, nome, carga_horaria)

No drawDB

  • Adicione uma tabela chamada ALUNO.
  • Inclua os campos matricula, nome, email e id_curso.
  • Marque matricula como chave primária.

Depois

  • Adicione a tabela CURSO.
  • Inclua id_curso, nome e carga_horaria.
  • Marque id_curso como chave primária.
Campos

Configure cada campo

03
Nome

Use nomes claros

Prefira nomes como id_cliente, data_pedido, valor_total e cpf. Evite campo1 ou dado.

Tipo

Escolha tipos compatíveis

Use inteiro para identificadores numéricos, texto para nomes, data para datas e decimal para valores monetários.

PK

Marque a chave primária

Quando a chave for composta, marque todos os campos que fazem parte da chave.

CampoTipo sugeridoMarcação
id_clienteintegerPK
nomevarchar/textcampo comum
data_nascimentodatecampo comum
id_cursointegerFK para CURSO
Relacionamentos

Ligue as chaves estrangeiras

04

No modelo relacional, relacionamento aparece por meio de chave estrangeira ou tabela associativa.

1:N

FK no lado N

Arraste a conexão do campo FK para a PK da tabela referenciada.

N:M

Tabela intermediária

Crie uma tabela associativa com as FKs das tabelas participantes. Essas FKs normalmente formam a PK composta.

MATRICULA = (id_aluno PK/FK -> ALUNO(id_aluno), id_disciplina PK/FK -> DISCIPLINA(id_disciplina), data_matricula)
No drawDB: a tabela MATRICULA deve ficar entre ALUNO e DISCIPLINA, com conexões para as duas tabelas.
Conferência

Compare drawDB e lista textual

05

O diagrama no drawDB e o texto do modelo relacional precisam representar a mesma estrutura.

Mesmo nome

Toda tabela desenhada deve aparecer no texto como NomeTabela = (...).

Mesmos campos

Campos do drawDB e campos da lista textual devem coincidir.

Mesmas chaves

PKs e FKs do drawDB devem estar marcadas também no texto.

Erro comum: desenhar uma FK no drawDB e esquecer de escrever FK -> Tabela(campo) na lista textual.

SQL/DDL

Não entregue apenas o arquivo da ferramenta. Entregue também o modelo relacional textual no padrão pedido pelo professor.

Fluxo recomendado para a atividade

O drawDB entra depois do raciocínio

Primeiro identifique entidades, relacionamentos, cardinalidades e regras. Depois use a ferramenta para materializar as tabelas.

A entrega deve ser verificável

Quem ler sua resposta precisa conseguir rastrear cada FK até uma PK existente.

CLIENTE = (id_cliente PK, nome, cpf) PEDIDO = (id_pedido PK, data_pedido, id_cliente FK -> CLIENTE(id_cliente))
Fechamento

Desenhe as tabelas, mas explique o modelo.

O drawDB ajuda na representação visual. A nota vem da coerência entre o enunciado, o DER, as regras de mapeamento e o modelo relacional entregue.
